# 双语电子书流水线 · 使用说明

把「英文 epub（结构骨架）」和「中文 epub（译本血肉）」合成**段段对照的双语 epub**。
纯标准库实现，**零第三方依赖**；LLM 可选，不填 key 也能跑出成品。

---

## 0. 先回答三个问题

| 你的问题 | 答案 |
|---|---|
| **有文档吗？** | 有，就是这份。技术细节另见 `bilingual-epub-design-v2.md`（22 节，含所有算法推导与实测数据）。 |
| **是命令行吗？** | 原本是，现在**两种都有**：命令行 `tools/run_book.py`，以及本地网页版 `tools/app.py`。 |
| **能打包成一个文件吗？** | 可以。已生成 `dist/bilingual-epub.pyz`，**63 KB 单文件**，换台装了 Python 的机器直接跑。 |

## 1. 三种用法怎么选

```
命令行 CLI ──→ 批量、脚本化、要精细控制参数
本地网页版 ──→ 偶尔用一次，点按钮看进度，不用记参数
单文件 pyz ──→ 换机器 / 给同事 / 不想配环境
```

三者共用同一套内核（`tools/bil/`），产物完全一致。

## 2. 安装与配置

**环境要求**：Python 3.10+（本机已有 3.13.12）。无 pip 依赖，不用 `pip install` 任何东西。

**配置 LLM（可选）**：

```bash
cp .env.example .env
```

编辑 `.env`（**注意放项目根目录，不是 `tools/`**）：

```ini
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-你的密钥
LLM_MODEL=deepseek-flash
LLM_CACHE_DIR=.cache/llm     # 请求结果缓存，重跑不花钱
LLM_WORKERS=64
LLM_RPM=2500
```

不配也行 —— 跳过 LLM 只会损失「小节细化」和「缺失段补译」，**段落对齐、图位锚定、注释回填全是确定性的，不依赖 LLM**。

> 重要：`load_dotenv()` 按**当前工作目录**找 `.env`，所以命令一律**在项目根目录执行**，不要 `cd tools` 里跑。

## 3. 用法一：命令行

### 3.1 三步走

```bash
# 第一步：结构体检（不花一分钱，看清两本书能不能对上）
python tools/probe_book.py

# 第二步：只跑一章试水
python tools/run_book.py --chapters chapter1 --build

# 第三步：全书出成品
python tools/run_book.py --all --build --title "智人之上 中英双语版"
```

### 3.2 加 LLM

```bash
python tools/run_book.py --all --llm --build --title "智人之上 中英双语版"
```

启用后会先打印成本预估：

```
[预估] 1179 pair / 14 章：约 59+6 次请求 · 输入 369,200 tok · 输出 38,810 tok → 约 ¥0.524（空闲时段）
```

跑完打印结算（命中缓存时显示 ¥0）：

```
[LLM 成本] 模型 deepseek-flash · 空闲时段
  本次 92 次请求全部命中本地磁盘缓存，未产生 API 调用 → ¥0（未消耗额度）
```

### 3.3 全部参数

| 参数 | 说明 |
|---|---|
| `--en PATH` | 英文 epub 路径（默认为内置测试路径） |
| `--zh PATH` | 中文 epub 路径 |
| `--chapters chapter1,chapter5` | 只跑指定章节，逗号分隔 |
| `--all` | 全书 |
| `--build` | 生成 `build/<书名>_bilingual.html` + `build/<书名>_bilingual.epub` |
| `--dump` | 额外导出 `review.md` 对照稿，供人工抽查 |
| `--out DIR` | 输出目录（默认 `build`） |
| `--title STR` | 书名；**留空则取中文版 `dc:title` 并加「（中英双语版）」后缀** |
| `--llm` | 启用 LLM 细化 / 勘误 / 补译 |
| `--concurrency N` | 章节级并发（默认 4） |

### 3.4 ⚠️ 章节 key 的坑

章节 key 是 **`chapter1`**，**不是 `ch1`**。传错会**静默跑 0 章**（不报错）。

其他合法 key：`prologue`、`part1`、`epilogue`、`ack`。

查看全部 key：

```bash
python -c "import sys;sys.path.insert(0,'tools');from bil import epubparse as E,structure as S;ze,zz=E.open_epub('en.epub'),E.open_epub('zh.epub');print([c.key for c in S.map_chapters(S.load_docs(ze,E.read_spine(ze)),S.load_docs(zz,E.read_spine(zz)))])"
```

### 3.5 读运行报告

每章一行摘要：

```
== chapter5 · Chapter 5 / 第五章 抉择：民主与极权制度简史
   脚注 126 ↔ 切注 108 (nl=0.94)  小节 9/9  段 214/198 (Δ-16)  覆盖 214/214 ✓
   pairs 210 匹配 210 缺中文 0 多余中文 0 多对 4 bad 2 (1%) FAIL小节 0 小节映射=DP
```

需要看懂的三个数：

- **`覆盖 214/214 ✓`** —— 关键指标。英文段落是否被 100% 覆盖。打 ⚠ 说明有丢段。
- **`pairs 210` 但 `段 214`** —— **正常**。`pairs` 数的是「配对对象」，一个对象可以含多段英文（多对一）。
- **`Δ-16`** —— 中文比英文少 16 段，通常是中文版删减，`--llm` 会补译。

全书跑完的总结行：

```
段落对 1163 · 命中中文 1149 · AI补译 0 · 待补 14 · 告警 19
```

## 4. 用法二：本地网页版

```bash
python tools/app.py
```

自动打开浏览器 → `http://127.0.0.1:8765`

页面操作：

1. 选**英文 epub**、**中文 epub**（点击虚线框选文件）
2. 填书名；想省时间可在「只跑指定章节」填 `chapter1,chapter5`
3. 勾选是否**启用 LLM**（不勾＝纯确定性对齐，零成本，全书约 5 秒）
4. 展开 **「LLM 设置」** 填接口信息（首次需要，见下节）
5. 点 **开始合成**
6. 看进度条 + 实时日志 + 章节统计表
7. 完成后下载：**中英对照 epub** / **仅中文 epub** / **仅英文 epub**，或**在线预览 HTML**

参数：

```bash
python tools/app.py --port 9000      # 换端口
python tools/app.py --no-browser     # 不自动开浏览器
```

### 4.1 在网页里配置 LLM（不用手改 .env）

「启用 LLM」勾选框下方有一个可折叠的 **「LLM 设置」** 面板：

| 字段 | 说明 |
|---|---|
| 接口地址 Base URL | OpenAI 兼容地址，如 `https://api.deepseek.com/v1` |
| API Key | 密钥，**留空 = 不启用**；已有值时不填不会覆盖 |
| 模型 ID | 如 `deepseek-chat` / `gpt-4o-mini` |
| 并发数 / RPM | 并发线程数与每分钟请求上限，留空用默认 |
| 请求缓存目录 | 默认 `.cache/llm`，重跑同内容不花钱；留空关闭 |

面板顶部有**一键预设**：DeepSeek / OpenAI / 通义千问 / Moonshot / 本地 Ollama，点一下自动填好地址和模型，你再补 Key 即可。

两个按钮：

- **测试连接** —— 立刻发一次最小请求验证。成功会显示模型回复和耗时（如「正常 · 609 ms」）；失败会明确告诉你是 Key 为空、还是地址/模型名不对。**测试不写盘**，可以放心试。
- **保存到 .env** —— 写入项目根目录的 `.env`，**并对当前运行中的进程立即生效，不用重启**。已加入 `.gitignore`，不会入库。

面板标题右侧有个状态圆点：<span>灰/红</span> = 未配置，<span>绿</span> = 已配置。点开时会自动读取现有 `.env` 并回填，所以你可以可视化地改，而不是对着一堆等号。

> 安全性说明：写入采用「**空值不覆盖**」策略 —— 只改模型名时，Key 会保持原样，不会被清空。想显式清空某个值，需要手工编辑 `.env`。文件权限会尝试设为 `600`（Windows 上语义有限）。
>
> 手工编辑 `.env` 的方式仍然有效，两者不冲突：网页改的是同样那 6 个 `LLM_*` 键，其余行（注释、自定义键）原样保留。

### 4.2 左侧边栏：直接读文档

页面左边有一条常驻侧边栏，分两组：

- **工作台 → 合成** —— 就是上面的上传界面
- **文档** —— 点开直接读项目里的 Markdown，不用去翻文件

内置四份：**项目总览**（`README.md`）、**使用说明**（本文件）、
**工具说明**（`tools/README.md`）、**技术设计**（22 节设计文档）。

实现上是**白名单制** —— 服务端只认 `DOCS` 里列出的那几条相对路径，
`../../etc/passwd`、`.env`、绝对路径一律 404，不会变成任意文件读取漏洞。

想加自己的文档，编辑 `tools/app.py` 顶部的 `DOCS` 列表即可（文件不存在会自动隐藏）。

窄屏（<860px）下侧边栏收起，左上角会出现 **☰ 目录** 按钮，点开可切回。

**限制说明**：

- 同一时刻只允许一个任务（避免 `.cache` 和 `build/` 竞争），重复提交会返回「已有任务在运行」。
- 上传的文件落在 `uploads/`，成品仍在 `build/`。
- 全书 + LLM 大约几秒到一分钟（缓存全中约 5 秒，真发请求约 47 秒），
  页面会一直轮询进度，别关标签页。
- **实测基线**（本书 1163 段对，普通笔记本）：不勾 LLM **4.3 秒**；
  勾 LLM 但缓存全中 **4.4 秒**；32 线程真发请求约 47 秒。
  对齐阶段此前要 20 秒以上，其中九成花在重复计算上（`en_words`
  逐词跑正则 + 代价函数每次重算整章长度数组），已改为预计算缓存，
  **输出逐字节不变**。

### 网页版「试对齐」：粘贴两段文字看对齐效果

左边贴英文、右边贴中文（一行一段），后端直接跑确定性 DP 返回中英对照
排版，**不调 LLM、不写盘、不进流水线**：

- 输入后自动对齐（防抖 350ms），也可以点「立即对齐」；
- 顶部显示「共 N 对 · 英文 x 段 / 中文 y 段 · 未匹配 z · 耗时 xx ms」；
- 配不上的段落显示「〔未匹配到中文〕」—— 这正是中文版缺段时的样子。
- 接口是 `POST /api/align`（JSON `{en, zh}`），想接自己的工具可以直接调。
- 「保存到 .env」写在**启动服务时的工作目录**下。单文件 `.pyz` 在别处运行时，会在那个目录新建 `.env`。

### txt 材料对齐（v1）

上传框同时收 `.epub` 和 `.txt`，可以**直接拖两个纯文本进来对齐**（比如
译稿和原稿都只有 txt 版）：

- 两侧必须同为 txt（一边 txt 一边 epub 不支持，会明确报错）；
- 编码自动探测：utf-8 / gbk / big5 都行，不必转码；
- **章标题行**自动识别：`第N章 …`（汉字或阿拉伯数字）、`Chapter N …`
  （数字或单词）、序章/序言/结语/致谢/Chapter 等常见模式；
  识别不出章标题且两边都是单文档时，整本按 1:1 对齐兜底；
- txt 没有锚点，**注释回填、插图、元数据/封面自动跳过**：成品无封面、
  扉页书名取自中文 txt 文件名（或手动填书名），其余（段落 DP 对齐、
  LLM 补译、长度比体检、双语渲染、微信读书目录/弹窗标记）全部照常。

## 6. 产物说明

跑完在 `build/` 下**一次给你四个文件**。文件名**带书名**（下表的 `<书名>` 是中文版书名，
例：`智人之上：从石器时代到AI时代的信息网络简史_双语.epub`）：

| 文件 | 用途 |
|---|---|
| `<书名>_双语.html` | **单文件网页版**，浏览器打开即可读。顶部「阅读模式」可切换**中英对照 / 仅中文 / 仅英文**。 |
| `<书名>_双语.epub` | 双语对照 EPUB3，可导入微信读书 / Apple Books / Calibre。**封面右上角有「双语」角标**，书架里一眼和原版区分。 |
| `<书名>_中文.epub` | **仅中文** EPUB，纯中文阅读体验，直接可发。封面无角标。 |
| `<书名>_English.epub` | **仅英文** EPUB，纯英文版。封面无角标。 |
| `review.md` | 仅 `--dump` 时生成，段落级对照表 + `r` 比值 + ⚠ 警告，供人工抽查。 |

> 后缀用中文「双语」而不是 bilingual：**微信读书对个人传书显示的书名取自
> 文件名**，英文字符会原样露在书架里（用户要求用中文）。角标由 Pillow
> 精准叠加在封面右上角（生成式重绘会毁掉封面原有文字，不用）；缺 Pillow
> 时自动跳过、封面原样。角标**只加在双语版**，单语分册用原封面。

### 元数据与封面沿用中文版

成品的**作者、出版社、出版日期、ISBN、封面图都从你上传的中文 epub 里读出来**，原样带过去：

| 字段 | 来源 |
|---|---|
| 书名 | 中文版 `dc:title`，自动加「（中英双语版）」后缀 |
| 作者 | 中文版 `dc:creator`（如「尤瓦尔·赫拉利」） |
| 出版社 / 日期 / ISBN | 中文版 `dc:publisher` / `dc:date` / `dc:identifier` |
| 封面 | 中文版 `<meta name="cover">` 指向的那张图，写成 `OEBPS/images/cover.*` + 封面页（spine 第一项） |

中文版缺的字段（比如没有简介）会用英文版补；两边都没有才留空。
实现在 `tools/bil/bookmeta.py`，`dc:subject` 里像「关注TG频道@xxx」这类盗版书广告会被自动过滤。

> 以前作者写死成 "Yuval Noah Harari"、封面干脆没有，换本书就穿帮。

分册书名不会叠后缀：双语版是「…（中英双语版）」，单语分册自动换成「…（中文版）」/「…（英文版）」。

### 三种阅读模式

`bilingual.html` 顶部有模式切换（单选按钮，不会出现「两边都空」的怪状态）：

```
中英对照  ←  段段对照，默认
仅中文    ←  隐藏所有英文段
仅英文    ←  隐藏所有中文段
```

### 扉页（titlepage.xhtml）

spine 顺序：**封面 → 扉页 → 正文**。扉页上按传统书籍版式列出：

| 项目 | 来源 |
|---|---|
| 书名 | 中文版书名 +「（中英双语版）」 |
| 原著书名 | 英文 epub 的 `dc:title` + 副标题（`Nexus: A Brief History…`） |
| 作者 | 中文版 `dc:creator` |
| 译者 | 中文版权页的「译者:」字段（这本书是林俊宏），OPF 里没有就扫正文前的版权页 |
| 出版社 / 出版时间 / ISBN | 中文版元数据 + 版权页 |
| 字数 | 实际统计：中文按汉字数、英文按单词数（本书 23.1 万字 + 13.6 万词） |
| 版权 | `dc:rights`（`Copyright © 2024 by Yuval Noah Harari`） |
| 声明 | 固定文案：自动生成的中英对照本、仅供个人学习、著作权归原作者、禁商用 |

epub 元数据里同步写入：`dc:contributor`（role=trl，译者）、`dc:rights`、
`dc:source`（原著书名，译作的标准字段）、`dc:identifier`（ISBN）、字数
（`word_count` / `en_word_count` 自定义 meta，Calibre 可读）。

### 章节标题：中英各占一个独立标题元素

```xml
<h2 class="ct en-h" id="ch5">Decisions: A Brief History of Democracy and Totalitarianism</h2>
<h2 class="ct zh-h">第五章 抉择：民主与极权制度简史</h2>
```

中文不再是塞在英文 `<h2>` 里的 `<span>`，而是**两个同级标题**：微信读书里
上下两行各自独立、字号互不干扰，目录里也是两条；小节标题（`h3.st`）同理。
CSS 让两行紧挨着（`.en-h { margin-bottom: .22em }` + `.zh-h { margin-top: 0 }`），
视觉上仍是一组。单语版整元素删除对应语言。

字号基准：英文章标题 `1.5em`、中文章标题 `1.2em`（≈ 英文的 80%）；英文节标题
`1.14em`、中文节标题 `.98em`。⚠ 拆成兄弟元素后，中文标题的 `em` 是相对父级
body 解析的，**不是**相对前面的英文标题 —— 若照搬 span 时代的 `.8em`，
中文会缩得比正文还小。改字号时按 body 基准直接写，别按「英文标题的倍数」写。

### 注释标记：三套机制叠加（微信读书弹窗靠 alt，2026-09 调研）

正文里的 `[12]` 一共挂了三层标记，各阅读器各取所需：

```xml
<a class="noteref duokan-footnote" epub:type="noteref" href="#ch5n12"><sup>[12]</sup>
  <img class="qqreader-footnote" src="images/note.png" alt="注12：注释全文…"/></a>
…
<aside class="note" epub:type="footnote" id="ch5n12">
  <ol class="duokan-footnote-content" style="list-style:none">
    <li class="duokan-footnote-item"><p><b>[12]</b> 注释正文…</p></li>
  </ol>
</aside>
```

| 机制 | 谁在用 | 说明 |
|---|---|---|
| `href` 跳转 | 所有阅读器兜底 | 跳到章末注释区 |
| `epub:type="noteref"/"footnote"` | iBooks / Kobo / Thorium | EPUB3 标准 |
| **注图标 + alt 藏全文** | **微信读书** | 书城书同款：`<img class="qqreader-footnote" alt="注释全文">`，点击弹 alt |

- 微信书城书其实有两种注释样式：弹窗式（图片 + alt 藏全文）和
  跳转式（普通上标链接）—— **跳转本身是微信的合法注释形态**；
  纯 noteref 语义它不解析，所以个人传书之前只会跳转。
- 注区结构对齐多看规范：`duokan-footnote-content` 挂 `ol`、
  `duokan-footnote-item` 挂 `li`（此前挂在 aside 上，微信读书实测无效）。
- ⚠ **个人传书能否弹 alt 没有公开的成功实证**（书城书确定弹；社区
  通用模板作者自己都没测成微信读书）—— 这是「最接近书城书」的试验方案。
- ⚠ 若听书 TTS 把 alt 念出来（每处注标读一遍注释），回退方法：去掉
  `note_mark()` 里的 img，仅保留数字 + 跳转。
- 注释和引用必须在**同一个 XHTML 文件**里（微信弹窗/跳转都要求同文件），
  大章拆分时注释体积已预先计入各分片预算。
- ⚠ **绝不能给 `.note` 设 `display:none`** —— 阅读器本来就会藏起
  footnote、点击时弹出，再藏死就永远显示不出来。

### 目录：EPUB3 nav + EPUB2 NCX 双目录（微信读书只认 NCX）

包里同时写了两个目录文件，内容永远一致（同一份条目生成）：

| 文件 | 标准 | 谁在读 |
|---|---|---|
| `nav.xhtml` | EPUB3（`epub:type="toc"`） | Readest、Calibre、Thorium 等新阅读器 |
| `toc.ncx` | EPUB2（navMap/navPoint） | **微信读书**、多看系内核 |

⚠ 只有 nav.xhtml 没有 toc.ncx 时，微信读书不会报错，而是**退化成扫描
文件内锚点自己拼目录** —— 脚注 aside 的 ID（`ch0n1`…这种）全被当成
目录项展示，看起来像目录坏了。manifest 注册 `<item id="ncx">` +
spine 写 `toc="ncx"`，双保险。

### 大章自动拆分 + 续片登记进目录（微信读书实测）

微信读书对**超大单章**会丢内容（社区实测 1.6MB 的章中间整段消失，
<100KB 是安全值），所以构建时把大章按**小节边界**切成多个 spine 文件，
每片 <96KB。但只拆不登记目录会被微信读书惩罚 —— 它会把「**目录里没
登记、却躺在 spine 里**」的文件自动挂成父章的子条目，标签退化成文件
`<title>`（实测显示成 `Chapter 4`×3、`Chapter 5`×4 这种垃圾条目；
此前单文件 >128KB 时代它按字节切虚拟子节、标签 `Chapter 4_1`，是同一
行为的两种表现）。

对策：**每个续片作为子 navPoint 明确写进 toc.ncx 和 nav.xhtml**，标签取
该片首个小节标题（双语格式 `中文小节名 · English section`）。微信读书
读 NCX 是实测可靠的（章级标签一字不差），没有可猜的东西自然不再编垃圾。
目录嵌套只到第二层 —— 更深的层级社区实测会丢。其余要点：

- 切分预算按 **UTF-8 字节**实算（中文 3 字节/字，按字符数切会超标）
- 每片引用到的**注释体积预先计入预算**，注释跟着引用走进各自分片
  （微信弹窗要求注释和引用同文件；先切后搬会把首批片撑爆）
- 英文兜底注释的 class 是 `note note-en duokan-footnote-item`，
  处理时必须和普通 `note` 一起认，否则整条丢失

另外：微信读书对**个人传书**显示的书名取自文件名（见上节）。

### 正文里的两个小图标（听书 TTS 不读出）

正文中有两个行内小图标，标出特殊来源的段落；图例写在**扉页**：

| 图标 | 含义 |
|---|---|
| 紫色「AI」 | 该段中文为 LLM 补译（纸书中文版未收录；双语版 147 处） |
| 橙色「审」 | 该段中文因内容审查删改，已按英文原版修复（133 处） |

要点：

- 图标是 **28×28 的无文字 PNG**，标签 `<img alt="" aria-hidden="true">`
  —— 听书 TTS 只读文本节点、跳过图片，所以微信读书听书**不会念出**
  「AI译」「内容审查修复提示」这类字样。⚠ alt 必须为空：alt 里有文字
  照样会被读出来。
- ⚠ **epub 里图标必须是真实图片文件**（`OEBPS/images/icon-*.png` +
  manifest 登记）—— 实测微信读书**不渲染 data URI 图片**（readest 里
  正常、微信读书里空白，2026-09 踩过；书里封面和插图是真实文件、
  显示正常，唯独 data URI 的图标不显示）。HTML 单文件预览没有
  manifest、必须自包含，仍用 data URI。
- 两个标记都是**渲染层自己加的**（`build.py` 的 `mt_flag()` /
  `censor_note()`），不是 LLM 输出 —— `llm.py` 的提示词本来就限定
  「只输出译文 / JSON 数组 / 修复后的段落，不要任何说明」。想换图标
  重跑 `tools/gen_icons.py`（Pillow 生成，base64 写回 `build.py`）。
- 审查修复段与正常段落**同样式**（保证阅读流畅），只多一个段首图标。
- 单语版处理：中文版**保留** AI 图标（补译标记对纯中文读者仍有意义）、
  **去掉**「审」图标（修复段的文字保留，仅去图标）；英文版两者都无。
- 图例跟随版本：双语版两行、中文版一行、英文版无。

### 单语 EPUB 是真单语

`chinese.epub` / `english.epub` 不是靠 CSS 藏起来的 —— 生成时**直接把另一种语言的元素从 XHTML 里删掉**，所以：

- `chinese.epub`：`class="en"` 出现 **0 次**，英文词残留仅 26,688（全是注释里的英文书名/期刊名，本来就该保留）
- `english.epub`：`class="zh"` 出现 **0 次**，汉字残留仅 4,163（全是注释里的「参见」「编者注」等中文编辑注）
- 目录也各自本地化：中文版目录是「第一章 信息是什么？」，英文版是「Chapter 1」

### 成品包含什么

- **段段对照**：每段英文下面紧跟对应中文（多对一/一对多都已处理）
- **中文目录**：`第五章 抉择：民主与极权制度简史 · Chapter 5`，中英并列
- **注释双语**：正文中的 `[12]` 可点击跳转，文末注释区中英并排；中文版缺的注释用英文原注兜底并标「英文原注」
- **图位锚定**：图片按序位挂到对应段落，中文版缺图时降级用英文原图
- **AI 标记**：LLM 补译的段落打紫色「AI」小图标，审查修复段打橙色「审」
  小图标 —— 都是无文字图片，**听书 TTS 不会读出**；图例见扉页

python tools/run_book.py \
  --en "D:/books/SomeBook (English).epub" \

## 7.1 测试用小样本（强烈推荐）

全书 5.6 MB，每次调试都跑一遍太慢。用这个从原书抽单章做成小测试集：

```bash
python tools/make_test_ch5.py              # 默认抽 chapter5
python tools/make_test_ch5.py --build      # 顺带出双语成品
python tools/make_test_ch5.py --llm        # 顺带跑真 LLM（会花钱）
```

产物在 `build/test/`：

| 文件 | 内容 | 大小 |
|---|---|---|
| `en_chapter5.epub` | 仅英文第 5 章 | 234 段 / 180 KB |
| `zh_chapter5.epub` | 仅中文第 5 章 | 325 段 / 168 KB |

直接把这两个文件拖进网页版就能跑。统计结果与全书**完全一致**
（脚注 126 / 切注 108 / nl=0.99 / 段 214↔198 / FAIL 小节 1），
但速度快得多，适合反复调试。

> 想换成别的章节：`--chapter chapter1`。章节 key 用 `--probe` 查。

### 输出目录是分开的，别互相覆盖

正式成品和试跑产物写入**不同的目录**，试跑永远盖不到正式成品：

| 目录 | 谁写 | 内容 |
|---|---|---|
| `build/` | 正式任务（网页「开始合成」、CLI `--all --build`） | 全书成品 |
| `build/test/` | `make_test_ch5.py` | 单章样本（输入用） |
| `build/demo/` | 网页「载入测试样本」按钮、`make_test_ch5.py --build` | 单章成品 |

网页结果卡片里会显示**产物目录**一行，下载的也是本次任务对应目录里的文件。

> 曾踩过的坑：样本生成器和试跑按钮都硬编码写 `build/`，一次试跑就把全书成品
> 换成了第五章（447 KB → 362 KB）。现在已按 `out_dir` 参数分流，改过之后
> 实测跑完试跑，`build/*.epub` 时间戳纹丝不动。

**先体检再跑**：新书第一步永远先跑 `probe_book.py`，确认章能对上、每章段落数差距是否合理。

## 8. 常见问题

**Q：`--chapters ch1` 跑出来 0 章，没报错？**
A：key 写错了，是 `chapter1`。改对即可。

**Q：报 `.env` 找不到 / LLM 没生效？**
A：`.env` 必须在项目根目录，且命令在根目录执行。`cd tools` 里跑会读不到。**网页版可以在页面上直接填并保存，不必手改文件**（见 4.1）。

**Q：网页上点了「保存到 .env」但下次打开又是空的？**
A：`/api/config` 读取的是**服务进程所在目录**的 `.env`。如果你换了个目录启动（比如把 `.pyz` 拷到别处跑），那读的是新目录 —— 在哪个目录启动，就在哪个目录存。

**Q：某章 `覆盖 210/214 ⚠`，丢段了？**
A：先看 `review.md` 里该章段落对照。多数是中文版删减，加 `--llm` 会补译；若是对齐错位，加 `--llm` 会走窗口细化修正。

**Q：成本怎么控制？**
A：① 先不勾 LLM 跑一遍看结构对不对；② 勾了 LLM 时输入命中缓存是**几厘钱**级别；③ 空闲时段（非工作日 9-12、14-18 点）是**半价**；④ 重跑全靠 `.cache/llm` 缓存兜底，实测可做到 ¥0。

**Q：缓存到底存了什么？为什么要缓存？**
A：存的是 **LLM 的 `chat()` 返回结果**，一对一写进 `.cache/llm/<sha256前32位>.txt`，
   键 = `sha256(system + "\n---\n" + user)`（见 `tools/bil/llm.py` 的 `_key`）。
   只缓存文本，不缓存图片、不缓存 epub。

   用处是**重复跑同一本书不重复花钱**。实测：全书 92 次请求、418k 输入 token，
   第一次约 ¥0.5；第二次因为提示词完全一样，92 次全部命中本地磁盘缓存，
   **API 一次都没调用，¥0**。改一个段落只会重算那一段，其余照旧命中。

   关掉它：把 `.env` 里的 `LLM_CACHE_DIR` 设成空字符串（注意不是删掉这行 ——
   删掉会回落到默认 `.cache/llm`）。

   ⚠️ **连通性测试必须绕过缓存**，否则同一句提示词会直接读磁盘返回，
   于是错误 API Key 也能「0 ms 成功」。网页的「测试连接」已强制
   `cache_dir=""` + 提示词拼时间戳，保证每次都是真请求。

**Q：网页里点下载出现「未发送任何数据 / ERR_EMPTY_RESPONSE」？**
A：2026-09 已修复。原因是下载响应头里塞了中文文件名，`http.server`
按 latin-1 编码响应头直接炸掉处理线程。现在中文走 RFC 5987 的
`filename*`（浏览器认真实文件名），引号回退名保持纯 ASCII。若你在
旧版本遇到，重启服务即可。

**Q：成品没有封面 / 作者显示成别人？**
A：封面和元数据都从**中文 epub** 里读。如果中文 epub 本身没写封面
   （OPF 里没有 `<meta name="cover">`），成品就没有封面 —— 换一个带封面的中文版，
   或在 Calibre 里给它加个封面再跑。作者同理，取 `dc:creator`。
   想确认读到了什么：CLI 跑 `--build` 时会打印一行
   `[元数据] 书名 … · 作者 … · 出版社 … · 封面 有/无`。

**Q：封面为什么是中文版的，不是英文版的？**
A：`bookmeta.pick_meta(zh, en)` 优先用中文版，中文版缺的字段才用英文版补。
   想反过来就改调用顺序（`pick_meta(en, zh)`）。

**Q：注释为什么有些是英文的？**
A：中文版（逆向来源）注释常常不全，实测某章只有 108/126 条。缺的条目用英文原注兜底，并标「英文原注」标记，比指向失效锚点好。

**Q：能改样式吗？**
A：改 `tools/bil/build.py` 里的 CSS 常量段，重跑 `--build` 即可。
