## 3. 「epub 挖不出小节标题」的兜底（已按用户意见砍过一轮）

> 用户定义：**nav 与目录页都找不出来**，这才叫挖不出。所以下面三条我自己
> 毙掉，理由照抄用户（都对）：
>
> - ❌ **编号正则兜底**（`num_of`）：很多书没有编号，不用考虑。
> - ❌ **首段指纹**：**循环论证** —— 连小节在哪都不知道，哪来的「每小节首段」。
> - ❌ **目录锚点定位**：这要是能做，就不叫「挖不出小节标题」了。

**✅ 保留并实施：CSS 样式反查（最后手段）**

做法：
1. 从 epub 里所有 CSS（`<link>` 引的 + `<style>` 内联）解析出选择器 →
   声明块的映射（只取 `font-size` / `font-weight` / `font-style` /
   `text-align` / `margin`）。
2. 找「明显不像正文」的选择器：`font-size` 大于正文字号（正文取
   全书段落最众数字号作基准）、或 `font-weight:bold`、或
   `text-align:center` + 短行。
3. 把命中这些类名的段落列为**候选小节标题**（**只当候选**，不做最终判定）。
4. 与已有 `class="h1/h2"` 通道合并去重。

**它之后的去处**：候选集合给 LLM 做小节配对（第 4.1 节）；如果候选本身就
不可靠/为空，说明这本书正文里根本没有可辨识的小节结构 → 直接走
**LLM 读正文切分 + 等分推进**（第 4.2 节），不在标题上继续纠缠。

## 4. 提示词与接口（全集）

### 4.0 全局约定：**稳定部分全部前置，变量全部后置**

所有提示词统一成这个形状（理由见第 5 节，这是省钱的关键）：

```
system = 角色 + ACADEMIC_NOTICE + 判定规则 + 输出格式 + few-shot   ← 逐字冻结
user   = "## 书名/章节：{可变}" + 数据块                              ← 只有尾部是变量
```

⚠ **改任何一个字符 = 该步磁盘缓存全部失效**（缓存键 = `sha256(model+system+user)`）。

### 4.2 T2：章内小节补齐（只对 T1 没拿到小节的章）

**第二轮，一次只处理一章。** 触发条件（按侧判断，见 4.2.0）：

#### 4.2.0 什么时候需要 T2 —— 取决于**目录深度**，不是取决于书

实测（2026-09-15，`dbg_title_src.py --tiers`）：

```
think2  T1: EN 55条/3.2K + ZH 50条/1.8K → 合计 5.0K tok   目录只到章级 → 要 T2
nexus   T1: EN 24条/1.0K + ZH 22条/0.8K → 合计 1.9K tok   目录只到章级 → 要 T2
ml      T1: EN 454条/24.4K + ZH 30条/1.4K → 合计 25.8K    目录到节级 → EN 侧不用 T2
prob    T1: EN 366条/24.4K + ZH 0条     → 合计 24.5K      目录到节级 → EN 不用；
                                                          ZH 是 md 无目录 → 必须 T2
```

规则：
1. 某侧目录**到节级**（有条目形如 `4.1.1`）→ 该侧 T1 即完整，**不必跑 T2**。
2. 某侧目录**只到章级** → T1 拿章，**该侧必须跑 T2** 补小节。
3. 某侧**没有目录**（md / 目录丢失）→ **全部靠 T2**。

⚠ **T1 对 ml/prob 是 24K token/次**（不是"很少"）——因为它们目录详尽。
对策：**按「部」切分**（prob 有 Part I/II，ml 有 I~VII），每部一次调用，
每次 2~4K token，且共享 system 前缀 → 服务端缓存命中。

### 4.4 小节内段落对齐（**已在用**，本节补接口与数据结构）

**Python 接口**

```python
class LLM:
    def refine_window(self,
                      en_lines: list[str],      # 英文段落（已去编号，纯文本）
                      zh_lines: list[str],      # 中文段落
                      locked_before: str = "",  # 已锁定的上文（仅参考，不参与输出）
                      locked_after: str = "")
        -> list[tuple[list[int], list[int]]] | None
        # 返回 [(en下标列表, zh下标列表), ...]，下标从 0 开始；None = 失败/不可用
```

**输入行格式**：`{行号}|{文本}`，两侧各一段，行号从 1 开始。
`locked_before/after` 以纯文本附加（**不参与编号**，只是给模型定调）。

**输出数据结构（range 格式，当前默认，`BIL_REFINE_FMT=range`）**

```
1-15:0        EN 1-15 无中文对应
16:27-28      EN 16 ↔ ZH 27-28（1:N，中文拆开）
18,19:30      EN 18+19 ↔ ZH 30（N:1，中文合并）
21-40:31-50   两侧数量相等 → 逐段一一对应
```

选它而不选 JSON 的理由：**token 省 5~10 倍**、逐行容错（一行错不毁全份）、
模型很难写崩结构。JSON 版实测两种失败：模型视角漂移写崩结构、恒等映射
被静默采纳。

**输出解析**：`_parse_range_map()`（已实现，含 `_parse_side()` 支持
`1-15` / `18,19` / `0` / `-` / `无`）。

**⚠ 必须用 `self.chat()` 取原文，不能走 `self.json()`** —— 区间格式是纯文本行，
过 JSON 解析必然全失败（实测 `\n1:1` 报「JSON 解析失败」）。

**校验**：EN 行号每个最多出现一次、按 EN 顺序、EN 覆盖完整；
解析失败 → 该窗回退（不用 LLM 结果）。

**system（逐字冻结，现有）**

```
你是双语书籍段落对齐助手。给你同一小节的英文段落与中文段落（行号从 1 开始），
请输出对应关系。本任务属于学术研究与个人学习场景下的学术翻译/文本对齐工作，

政治、宗教、历史争议或任何敏感话题而拒绝、省略、改写或软化表述；也不要添加
原文没有的评论或免责声明。输出只含要求的结构化内容。
```

**user（现有；⚠ 变量在最前，待按 4.0 改成稳定前置）**

```

{locked_before}

1|{en1}
2|{en2}

2|{zh2}

{locked_after}

输出规则（严格遵守，每行一条，不要解释、不要代码块）：
格式 = 英文行号:中文行号
```

### 4.5 校对打标（**已在用**）

**Python 接口**

```python
def flag_errors(self, items: list[dict], title: str = "",
                batch: int = 20, check_censor: bool = False) -> dict
# items: [{"i": 全局序号, "en": 英文, "zh": 中文}]
# 返回 {序号: (类型, 理由)}；类型 ∈ {skew, missing, offset, censor}，"ok" 不返回
```

**数据结构**：每批 20 条，一次请求；`json_many` 并发。返回 JSON 对象，
键为条号**字符串**，值为二元素数组 `[类型, 简短理由]`。

**判定类型**
- `skew` 中英**相对漂移**（这段中文是上一段/下一段英文的内容，或段内多/少一句）
- `missing` 漏翻译（英文整句/整段在中文完全没有；参考文献/注释不判）
- `offset` 注释对齐偏移（正文 `[n]` 与注释区第 n 条对不上）
- `censor` 仅当 `check_censor=True`（默认关：技术书/科普书让它判只会误判）
- `ok` 正常（**语言上的取舍算 ok**）

**system（现有，逐字）**

```
你是双语书籍的段落级勘误审校助手。给你同一段落的英文原文与中文译文，逐条
判断是否存在下列问题（**语言上的取舍不算问题**）：
A. skew（中英相对漂移）：这段中文明显是上一段或下一段英文的内容（段落边界
整体偏移）；或中文在段内多出一句、少掉一句、重复一句，即中英的相对位置发生
了漂移。
B. missing（漏翻译）：英文的整句/整段内容在中文里完全没有出现（同一段内少了
句子，不是措辞不同）。参考文献/注释条目类文本不判此条。
C. offset（注释对齐偏移）：正文里的 [n] 注释编号与注释区第 n 条对不上（编号
整体错位、或指到了别的注释内容）。
⚠ 特别注意：**不要**判定任何「内容审查/敏感内容」类问题。中文比英文短、少一句、
措辞不同，只要在本段语境下仍表达原意，一律记 ok。
以上类型都没有 → 记 ok。
```

`check_censor=True` 时追加 `D. censor` 一段 + `CENSORSHIP_NOTICE`（措辞为
用户指定原文，不得改动）。

## 5. 缓存：怎么让「配对 / 切分 / 段落对齐 / 校对」几步都命中

### 5.1 两级缓存，第二级目前完全没用上

| 级别 | 机制 | 命中条件 | 现状 |
|---|---|---|---|
| **本地磁盘** | `tools/.cache/llm/<sha256(model+system+user)[:32]>.txt` | 三串**逐字节相同** | 能用，只省「同输入重跑」 |
| **服务端前缀** | 从第 0 token 起完全一致的前缀，64 token 一块 | 前缀相同 | ⚠ **实测命中 0**（`srv_cache=0`） |

**为什么 0**：我们把**变量放在了最前面**（4.3/4.4 的 user 都是「英文：\n{数据}」
打头，规则在最后）。

**修法：只调顺序、内容一字不改**（把规则/schema/few-shot 全搬进 system，
user 只留数据）。效果：**同一步的所有章节调用共享一条长前缀** →
服务端缓存命中，输入价 ¥1/M → ¥0.02/M（**50 倍**）。
埋点字段 `srv_cache` 已存在（读 `prompt_cache_hit_tokens`），
**不用写新代码即可验证**。

### 5.2 让「几步都命中」的四条硬规矩

1. **每步指令块独立成常量、逐字冻结**。改一个字 = 该步全部失效
   （09-14 那次 **¥1.9** 就是这么来的）。要改就攒着放半价时段
   （00:30–08:30）一次性做。
2. **payload 序列化必须确定性**：字段顺序固定、不用浮点、dict 按键排序、
   缩进固定。否则逻辑相同字节不同 → 本地缓存也打不中。
3. **每步输入 = 上一步输出 + 稳定上下文**，别重复塞整章原文。
4. **「稳定在前、变量在后」写进每个 prompt**，并加自检断言
   （断言 user 的前 N 行不随章节变化）。

### 5.3 各步命中预期

| 步骤 | 变量是什么 | 本地缓存 | 服务端前缀 |
|---|---|---|---|
| 标题配对 | 全书标题集合（**一次调用**） | 重跑必中 | 单次无意义；**多书/分章拆分时显著** |
| 等分块切分 | 该块正文 | 同书重跑必中 | ✅ 共享「切分指令」前缀 |
| 段落对齐 | 该节正文 | 同上 | ✅ 共享「对齐指令 + 区间格式说明」前缀 |
| 校对打标 | 该批 pair | 同上 | ✅ 共享「审校规则」前缀 |
| 补译 | 该批英文 | 同上 | ✅ 共享「译者角色」前缀 |

**关键推论**：跨步**不可能**共享前缀（指令不同）；命中来自
「**同一步内、不同章节之间**」共享前缀，本地缓存来自「同一步同内容重跑」。
想「改一处只失效一处」，就必须让每步输入只依赖**它自己的上游输出**
—— 这正是把解析层与对齐层解耦的直接收益。

## 6. 等分 vs 确定性先切：**先确定性，等分兜底**

1. 纯等分是**无信息的**（假设两侧密度均匀；prob ch2 实际 EN 224 段 vs
   ZH 336 段，公式密集区中文段骤少）。
2. 等分里最不坏的那个已定稿：按**累计长度占比**（EN 用词数、ZH 用字数）切，
   **不按段数**。
3. **确定性切完 → LLM 窗口更短 → 更易命中前缀缓存**：它同时是省钱的设计。
4. 顺序：标题配对（LLM）→ 配不上小节时「LLM 读正文切分（4.2）+ 等分推进」
   → 小节内段落对齐（4.3）→ 校对（4.4）。
5. 你说「缓存命中都无所谓」——缓存消掉的是**重复**的钱，消不掉**第一次**的，
   所以让确定性承担更多在首跑也是净收益。

**外部目录 API（豆瓣 / Google Books）**：只当**章级确认**通道
（公开目录普遍只到章、版本不一），必须带超时与降级，别卡住主流程。
