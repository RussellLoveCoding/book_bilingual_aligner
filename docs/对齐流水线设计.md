# 双语 epub 对齐流水线（现行设计）

> 2026-09-14 重写。取代 `bilingual-epub-design-v2.md`（v2 旧稿）与
> `review_ch1.md`（早期单章评审记录），两份已删除。

## 0. 一句话

**确定性只做「脚手架 + 裁判」；LLM 按需介入做对齐；长度比体检决定谁说了算。**

## 1. 流水线五阶段

| 阶段 | 做什么 | 谁做的 | 耗时 |
|---|---|---|---|
| ① 解析 | epub → 块（正文段/标题/图/表/注释/代码/引用） | 确定性 | 整本 <1s |
| ② 章级映射 | 文档配对（键匹配 → LLM 标题 → 文档级轻量 DP） | 键/DP 确定性；不确定时 LLM | <1s |
| ③ 段级对齐 | 段落配对（见 §2） | DP + LLM | 1–3s |
| ④ 格式挂载 | 图/表/注释/交叉引用挂到对应段 | 内容锚点 | <1s |
| ⑤ 渲染 | 双语 epub/html、封面角标、段落 class | 确定性 | 1–2s |

**硬约束（用户定）**：无模型对齐必须 **30 秒内**跑完；凡「慢且不准」的确定性
组件一律毙掉（曾把 130s 的章级映射砍到 0.3s）。

## 2. 段级对齐：闸门 + 分窗 LLM + 裁判

```
每章：
  扁平 DP 对齐（Gale-Church 长度比 + 自建 L1 词表；免费）
      ↓
  长度比体检：r = 中文字符数 / 英文词数，∈[1.0, 3.0] 为正常
      ├─ bad ≤ 15%（--llm-gate）──→ 采用 DP 结果，一次 LLM 都不调
      └─ bad > 15% ──→ 分窗 LLM 对齐（refine_window）
              · 窗口 40 段；DP 仅用于给窗口定位置（脚手架）
              · 锚点：图注编号（图1-8 ↔ Figure 1-8）+ 正文图表引用
              · LLM 只回 **mapping 元数据**，不下译文
              ↓
        验收三道：① 结构合法（不越界/不重复/英文覆盖≥70%）
                  ② bad 必须下降
                  ③ 中文散文段覆盖 ≥90%（代码段允许无对应）
              ↓
        逐小节裁判：DP vs LLM 取 bad 低者（仅 DP 体检达标时启用）
```

**为什么这样分工**：《思考，快与慢》这类书 DP 命中 97%，让 LLM 全程介入纯烧钱；
机器学习实战这类书 DP 被代码块冲垮（bad 90%），LLM 完胜。让体检在**每一章**
上决定用谁。

## 3. LLM 的六项工作

| 能力 | 用途 | 默认 |
|---|---|---|
| `map_titles` | 章级配对（只吃标题+段数） | 开 |
| `map_sections` | 小节配对兜底（标题+段数+首段预览） | 开 |
| `refine_window` | **段落对齐主力**（分窗、只回 mapping） | 开（体检不达标时） |
| `translate` | 补译「英文有、中文没有」的段 | `--ai-fill-missing`（关） |
| `flag_errors` | 勘误诊断：**skew 漂移 / missing 漏译 / offset 注释偏移** | **开** |
| `flag_errors(censor)`+`repair_censored` | 敏感审查改动检测与修复 | `--ai-repair-censor`（关） |

**censor 为什么默认关**：技术书/科普书不存在审查删改，让 LLM 判它只会误判
（把「语言取舍少一句」当成审查改动）。开了也只认「因宗教/伦理/道德/政治
敏感内容而做的删改」，语言取舍一律记 ok。

## 4. 评估策略（三层）

1. **机器体检**（每对）：长度比越界或单侧空 = bad；小节 bad>20% = FAIL。
   用途：LLM 准入闸门、LLM 结果验收、成品告警。
   ⚠ 只能查长度异常与单侧缺失，**查不出「长度都正常但语义错位」**。
2. **金标准**（离线）：MAC 人工平行语料 link-F1（0.942，对比 Hunalign 0.607 /
   Bertalign 0.909）；插图逐章顺序核对（`tools/check_figs.py`，think 20/20）。
3. **抽样人审**：随机对 + 最难小节逐条读（人判断，目前唯一能发现语义错位的手段）。

**目标指标（用户定义）**：每个英文段落（参考文献除外）都应落到一个 pair，
且该 pair 里有一段**正确**的中文 —— 语言取舍但语境保留原意算正确；漏译 /
多译 / 重复 / 段落漂移（skew）算错误。

## 5. 格式对齐（内容锚点，不用 LLM）

- **图**：图注编号匹配（图1-8 ↔ Figure 1-8）> 位置邻接（≤8 段）> 顺序认领；
  英文图回英文原文位、中文图跟对应中文段（两流各插各的）
- **表**：与图同机制（表29-1 类图注段匹配）
- **章名**：优先取 epub 目录（toc.ncx/nav），正文里常只有「第2章」
- **小标题**：记录 (段前位置, 标题) 后**原位渲染**，不在章首拼接合并
- **引用**：`<blockquote>` 内的段判为 quote，中文侧跟随英文格式
- **注**：`[n]` 标记 ↔ 注释区条目；中文注区不全时用英文原注兜底
- **段落 class**：英文 `en en_original`、中文 `zh zh_transed`（便于 CSS 定制阅读）

## 6. 成本

| 场景 | LLM 用量 | 花费 |
|---|---|---|
| 简单书（闸门全过） | 只做章级映射（~20 次调用） | ≈¥0.1（空闲时段减半） |
| 技术书（闸门大面积不达标） | 分窗 LLM 全面介入 | ≈¥2–3 |
| 书籍 token 量参照 | 输入约 7.5%、输出约 2%（≈53 万 token 的书） | — |

DeepSeek **高峰价 = 空闲价 ×2**（输入 ¥2 vs ¥1/M，输出 ¥8 vs ¥4/M）→
大跑放 00:30–08:30。

## 7. 迭代与回归

- 改动验证一律**单章**（`--chapters chapterN`，约 ¥0.02），整本只跑一次
- **回归**：`python tools/regress.py`（跑三本书，打印 指标对比 + 图序）
- 改指标类代码**必须核对 r 值本身**，不能只看 bad 总数
  （曾出 bug：LLM 路径的配对从没算过 r → 恒为 0 → 整章误判 100% FAIL）
