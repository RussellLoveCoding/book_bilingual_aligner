## 一·补2、**候选质量 = 精度**（2026-09-16 血的教训）

T2 精度从 75% → 100%，**一条都不是靠改提示词或改模型，全部靠清候选**：

| 喂进去的垃圾 | 例子 | 谁该拦 |
|---|---|---|
| md 的裸段落碎片 | `其中` / `满足不等式` / `比较 (7.20) 和 (7.21)，我们得到…` | md 只认 `#` 标题（已删 S4b 通道） |
| epub 单字碎片 | ml 中文的 `T` / `d` / `B` / `和` / `或` | `len(t) >= 2` |
| 章节尾固定块 | nexus 的 `注释 / Notes` ×7 | 页眉闸门（≥3 文件） |
| builder 残留 / 对话台词 | `〔本小节自动对齐未通过体检…〕` / `“可是你们的算法难道没看到…”` | `_is_noise()` |
| 上层结构混入 | think2 的 `两个系统`（部副标题）、`记分`（章名重复） | `lv >= 单元层级` + `strip_label` |

⚠ **根因是「候选挖掘」和「单元切分」各写了一套过滤**：`units()` 里四道闸都有，
`section_candidates()` 一道都没有。**两处必须共用同一套判据。**

## 二、LLM 侧：真正的「慢」在这里（已修）

**错误做法（v2，已废弃）**：把整本书的**四源候选**（几百条、带来源/文件/层级标记）
连同一个冗长 JSON schema 发过去。

| | v2（错） | v3（对） |
|---|---|---|
| 输入/本 | ml 32K · prob 56K token | **~950 token** |
| 输出/本 | 上万 token（nexus 一次 13,979） | **~220 token** |
| 单本耗时 | 2~3 分钟 | **<1 秒**（缓存命中 0 秒） |
| 四本合计 | **7.5 分钟** | **2.28 秒** |
| 四本成本 | ≈¥0.09 | **≈¥0.0015** |
| 结果 | prob 输出被截断成非法 JSON | P 100%×4 本，110/111 |
| schema | 我自己发明的（带 `en_title`/`zh_title`） | 用现成内核的 `[[0,0],[1,null]…]` |

**根因**：项目里**早就有这个内核**，我没看就直接手搓报文。

```
bil/llm.py
  cli.map_titles(en_titles, zh_titles)   # 章级：只传「序号|标题|段数」
  cli.map_sections(...)                  # 章内小节
  cli.refine_window(...)                 # 段落窗口细化
```
源码注释原话：「输入只有几十个标题，输出只有 mapping，单次约 2k token，
**是整套 LLM 能力里最便宜的一个**」。而且这些 prompt **逐字冻结**（改一个字
= 缓存全失效 + 结果可能变坏，源码里有 2026-09 的实测记录）。

⇒ **铁律：要发 LLM 前，先在 `bil/llm.py` 里找有没有现成内核。不要自己拼报文。**

## 三、本地侧：冷跑 11.8s 花在哪（已缓解）

- 同一本书被**解析两遍**：`titlesrc.collect_epub()` 一套、`sectmine.doc_order()`
  另一套，各自读遍所有 spine 文档 + CSS。
- ml 中文那本：**xhtml/css 只有 33 个文件、解压后 3.1MB**（94MB 全是图片），
  单遍 **2.4s** —— 慢在 `epubparse.read_doc` 对每个块跑一堆正则。
- 处置：`bil/fastcache.py` 磁盘缓存（`tools/.cache/parse/`，永不删）。
  ⚠ 缓存粒度必须下沉到**未过滤、未合并的原始行**（`titlesrc.raw_rows`）：
  把 `prefix`/`drop_repeats` 放进键 = 等于没缓存（实测照样 14s，踩过）。
  ⚠ 哈希必须用 sha256，不能用内置 `hash()`（跨进程随机化 → 永不命中）。

## 四、踩过并回退的坑

| 尝试 | 结果 | 教训 |
|---|---|---|
| 让 `doc_order()` 复用 `collect()` 的合并结果（省一遍解析） | **ml 英文塌成「1 个单元」**、nexus 小节数 95→123 | `merge()` 按 (文件,文本) 去重、层级取最浅 → 行集合变了 → `units()` 的「一文件一单元」判据失效。**已回退** |
| 只回 id 不回标题（想省输出 token） | nexus/think2 节级变 **0 对**，prob 返回非法 JSON | 省 token 不能靠改 schema；该用现成内核 |
| 用 `dbg_align_eval.gold()` 给 T1 打分 | think2 38 章全报「漏配」，实际 LLM 全对 | 金标准词表要与被测对象一致（目录标题 vs 正文真章名） |

## 五、想突破 2.08s 的唯一办法

**常驻 python 进程**（一次启动、后续走 socket）。用户明确说过
「长驻服务你别给我开，我自己开」→ **未做，等用户定**。
