# 勘误流水线设计：程序圈候选 + LLM 裁决

> 用户 2026-09-18 原话：「这个问题，你就没想出更好的方法了吗，实在不行，可以让
> llm 来判断，懂吗，DP 很有限的，不然我为啥用 llm。你需要编写一种程序策略，
> 与 llm 对接勘误，设计一下」
>
> 本文是**设计**，不含实现。定调：DP 当先验/分块/底线，LLM 在窗口内做语义裁决，
> 触发看「DP 不确定度 + 结构性疑点」，**不许用 DP 自评的 rate 当触发**。

## ★ 首要结论（2026-09-18 实测后修订）：先把「假缺陷」排掉，再谈 LLM

按用户定调「先有判据再有 LLM」，P0 做完后的实测结论是：
**用户点名的绝大多数「对齐错配」根本不是对齐问题，而是解析器把标题吃掉了。**

两个解析 bug，零 LLM 成本，修完全书：

| 指标 | 修前 | 修后 | 变化 |
|---|---|---|---|
| 命中中文 | 4341 | **4571** | **+230** |
| 待补 | 1406 | **1150** | **−256** |
| 告警 | 2368 | **1907** | **−461** |
| bookscan 整篇缺中文 | 1025 | **805** | **−220** |
| zh-only 丢弃 | 2232 | **1746** | **−486** |

**bug ①：CSS class 标题的字母后缀（`h2a`）被丢弃**（`epubparse._CLASS_HEAD_RE`）
剑桥社转制的精排 epub 用 `class="h2a"` 标记「同层级、排版略有不同」的标题。
旧正则 `(?:^|[\s_-])h([1-6])(?:[\s_-]|$)` 要求 `hN` 后紧跟分隔符或串尾，
`h2a` 的 `a` 两边都不满足 → **整条标题被当成正文段吞掉**，其下整棵小节树错位。
《概率论沉思录》中招 5 处，恰好覆盖用户点名的章节：

| 被吞掉的标题 | 所在章 | 用户是否点名 |
|---|---|---|
| `13.12.1 'Objectivity' of decision theory` | chapter19 | ✗（但 13.12 子树整层左偏一格） |
| `7.27.1 Terminology again` | chapter12 | ✅ **7.27** |
| `9.16.1 The irrationalists` | chapter14 | ✅ **9.16** |
| `4.8.1 Etymology` | chapter9 | ✅ **4.8** |
| `19.7.1 A paradox` | chapter25 | ✗ |

修 `13.12.1` 一处，chapter19 从 `EN 17 节 / ZH 18 节` 变成 `18/18` 且
**6 个子节标题与段数逐一对应**（`13.12.1`: 20/20、`13.12.2`: 10/10 …）。
其余 4 处中文版**确实没有**该子节（译本并入父节），修复后仍显示单侧——那是正确答案。

**bug ②：md 附录子节标题是裸行（`A.1 …`），被当正文**（`txtimport._bare_subhead`）
中文 md 里附录 A/B/C 的子节标题全是裸行（无 `#`），且以拉丁字母开头、
长度 >12 → `_MD_HEAD_RE` 与 `_bare_head` 都认不出。后果：

```
修前  附录A: EN 6 节 / ZH 1 节   → EN 的 A.1(36段) 配到「空」
修后  附录A: EN 6 节 / ZH 6 节   → A.1 36/36 · A.2 7/7 · A.3 15/15 …（编号链）
```

**这曾被误判成「中文版没译附录」**（`HANDOFF §6.11` 与旧总结把它归为
「A19 附录未译」）。实际译文**完整存在**（`A.1 柯尔莫哥洛夫概率系统`
连同四条公理全都有），只是结构上不可见。修完 `bookscan 整篇缺中文`
从 1025 段降到 805 段，附录 A/B/C 全部 1:1。

**教训（写进流程）**：看到「整块只有英文/零中文」，**先怀疑解析器丢了标题**，
不要先怀疑对齐算法，更不要先请 LLM。判据：两侧小节数悬殊（6 vs 1）而总段数
接近 → 一定是切分问题，不是配对问题。

## 一、为什么必须「程序 + LLM」而不是二选一

### 1.1 DP 的能力边界（已实测）

| 场景 | DP 表现 | 原因 |
|---|---|---|
| 中英段数接近、顺序一致 | **很好**（MAC F1 0.942 有词典时） | 长度比 + 编号锚点足够 |
| 中文把小节并进父节 | **正确**（§6.16 实测） | 单调对齐天然支持 |
| 中文重排章节顺序 | 差 | 单调假设被破坏（`chapter3` 整章左偏一格） |
| **两侧粒度不同**（英文用公式图、中文 OCR 成文字） | **错** | 段落数都不一致，长度比失效 |
| **中文整节未译**（Bibliography） | 无所谓 | 单侧输出是正确答案 |

⇒ DP 错的地方有一个共同点：**"这几段该不该配"不是长度问题，是语义问题**。
而这恰好是 LLM 擅长的。反过来，LLM 单独干不行：
- 全书 6000+ 对，全送 LLM = 成本失控（且大部分对 DP 已做对）；
- LLM 无位置感，会让它自己"发明"对齐，产生 §6.13 那种 88% 搬空的灾难。

### 1.2 正确的分工

```
程序（DP + 结构分析）           LLM
─────────────────────          ─────────────────────
① 全量对齐（底线）              ④ 只在「窗口」内做二选一/三选一
② 圈出「不确定」的窗口          ⑤ 返回**块级 N:M 分组**（不许切段）
③ 提供结构证据（图位/编号）      ⑥ 必须给出理由 + 置信度
```

**铁律（用户已定调）**：LLM 输出只能是**块级 N:M 分组**，不得在段内切边界。

## 二、核心：怎么圈出「值得问 LLM」的窗口

### 2.1 判据必须是「结构性不确定度」，不是 DP 自评 rate

❌ **不许用**：`bad_rate`、`rate` 这类 DP 自己算的分数（用户明确禁止，
且 §6.15 已证明这类文本分数不可靠）。

✅ **要用**：**多路径分歧 + 结构证据冲突**。

#### 判据 S1：DP 多路径分歧（测"DP 自己有多犹豫"）

> ⚠ **2026-09-18 实测否决（本判据作废，保留记录）**：
> 按下面写法实现（`k_range` 微扰 ±15%），全书扫出 **1596 个「分歧对」**，
> 而全书可对齐小节只有 **356 个** —— 候选比被审查对象还多，判据无信息量。
> 原因：`k_range` 只改动长度比的**夹取区间**，对绝大多数 pair 都足以让代价
> 排序交换，"敏感"几乎是普遍属性而非"不确定"的属性。
> **结论：不要用「改参数的扰动」当不确定度。** 要测 DP 的犹豫，必须看
> **同一目标函数下最优解与次优解的代价差**（marginal），而不是换参数的解差。
> 已实现为 `tools/dbg_candidates.py`（保留）+ 结论写进 `HANDOFF §6.17`。
> 当前唯一可用的触发判据是 S2/S3 + 结构疑点（见 §2.2）。

对同一节跑 DP 两次，第二次**微扰代价函数**（如 `LEX_W` 或 `GAP` 扰动 ±15%），
取两次结果的**差异对集合**：

```python
def unstable_pairs(en_ps, zh_ps, tol=0.15):
    """DP 在代价函数微扰下改了主意的那些对 —— 这是真正的'不确定'。"""
    base = align_section(en_ps, zh_ps)
    alts = [align_section(en_ps, zh_ps, gap_scale=1 + s, lex_scale=1 - s)
            for s in (tol, -tol)]
    key = lambda ps: {(tuple(p.en), tuple(p.zh)) for p in ps}
    b = key(base)
    diff = set().union(*(b ^ key(a) for a in alts))
    return base, diff          # diff 里的对 = 送 LLM 的候选
```

**优势**：不动用任何文本启发式；DP **自己说出来**哪些对是"勉强配的"。
**成本**：DP 是纯计算，跑三遍 ≈ 零成本。

#### 判据 S2：结构证据冲突（测"客观事实是否打架"）

三种**已知客观信号**，任一冲突即进候选：

| 信号 | 定义 | 冲突判定 |
|---|---|---|
| **图位 vs 文本** | 英文段是公式图（`visuals`），中文对应段是**纯文本**（无 `$`） | 中文不该在这儿有正文 → 可疑 |
| **编号锚点缺失** | EN 段含编号 `(x.y)`，但中文配对段不含该编号的**任何形式** | 中文可能整体错位一格 |
| **段数守恒** | 一个 pair 的 `en` 段数 + 下一 pair 的 `en` 段数 vs 对应 `zh` 段数 | 粒度不同（英文细、中文粗）→ 可疑 |

#### 判据 S3：单侧聚集（测"是否整块缺失"）

连续 ≥3 个「只有英文」的段落在同一小节内 → 该小节可能**整块未译**或**整块错位**。
（注意：脚注、Bibliography 会天然触发此判据 → 需要**先按小节类型白名单排除**。）

### 2.2 白名单：先扣掉「单侧是正确答案」的地方

> ⚠ **2026-09-18 实测修正（本文原估计过于乐观）**：
> 原写「能把候选量砍掉 80%」——**实测只有 22%**。
> `tools/dbg_onesided.py` 全书统计 2532 个单侧段：
>
> | 类型 | 段数 | 占比 |
> |---|---|---|
> | 判为「实质正文」 | 1975 | **78%** |
> | 元数据（短无句读） | 349 | 13.8% |
> | 短引导语 | 132 | 5.2% |
> | 公式行 / 脚注 / 题注 | 76 | 3.0% |
>
> 单靠「文本形态」白名单**区分不开**。真正区分得开的是**结构归属**：
> `tools/dbg_zhonly_locate.py` 用「数字锚点 + 拉丁串」反查英文侧，
> 对 1124 个长中文独有段（汉字 ≥40）判别结果：
>
> | 判定 | 段数 | 含义 |
> |---|---|---|
> | 英文侧全章无任何信号 | 321 | **中文独有，丢弃正确** |
> | 太短（<40 汉字） | 802 | 元数据/标签 |
> | 疑似错位 | **1** | 该修 |
> | 信号太弱 | 2 | 存疑 |
>
> ⇒ **长中文独有段里真正错位的只有 1 段（0.09%）**。所以白名单的正确做法是
> 「**先做内容反查（数字/拉丁串），查不到才算独有**」，而不是按文本形态猜。
> 另外 `tools/dbg_visual_adj.py` 验证过：单侧段里**92.9% 与图位无关**
> （图后引导语只占 3.9%、ZH 与 EN 图同位 2.4%），所以「图位」不能当主判据。

能把候选量砍掉的部分（**按结构归属，不按文本形态**）：

| 类型 | 判据（结构） | 处置 |
|---|---|---|
| 脚注正文 | 段落以 `数字+空白` 开头，且在切注区 | **排除** |
| Bibliography / References / 索引 | 所属 `cp.key` 在小节类型表里 | **排除** |
| 公式引导语 | 段尾紧跟 `visuals`（公式图），且段长 ≤40 | **排除** |
| 元数据行 | 长度 ≤24 且不含句读 | **排除** |
| 中文独有章 | `en_blocks` 为空 | **排除** |

### ★★ 关键发现：很多「块数差」是**脚注内联**，不是对齐错

**证据链**（`tools/dbg_fnwhere.py`，ch11/ch12/ch23 实测）：

```
chapter11 §24 '6.23 Comments'  EN36:ZH15（块数差 140%、成串英文独有 6/9）
  [EN] 主文流里以 [n] 开头的段：20 个   ← b[519]–b[540]，[1]…[20]
  [ZH] 主文流里脚注式段：0 个          ← 中文把脚注放在自己的注释区
  英文独有 13 段，其中脚注式 11 段（编号 [2,3,4,5,6,9,10,11,12,13,14]）
```

**机制**：英文原版**脚注印在页脚**，EPUB 转制时被**内联进主文流**；
中文译本的脚注在**自己的注释区**。于是英文主区凭空多出 20 段脚注
→ 块数差 36:15、成串英文独有 —— **但正文段本身对齐是对的**
（人审逐对：`EN[10]–EN[14]` ↔ `ZH[11]–ZH[13]` 一一对应）。

**为什么必须排除而不是送 LLM**：LLM 只能重排**给它的窗口**，
**没法把脚注搬进注释区**。送它 = 让 LLM 在一个「不该由它解决的问题」上乱配，
只会把本来正确的正文对改坏（这正是 §6.13「88% 搬空」的翻版）。

⇒ **判据写成"单侧段全部是脚注"才豁免**（不是"多数"）：
只要还有一个非脚注单侧，就仍可能是真错位。

### ⚠⚠ A/B 对照：**白名单不涨长度指标**（必须说清，别自吹）

同一份代码、同一份缓存，只切 `BIL_ERRFIX` 开关，重建两次：

| 配置 | 段落对 | 命中中文 | 待补 | 告警 | qa | bookscan | LLM 请求 |
|---|---|---|---|---|---|---|---|
| P1-only（无 `--llm`） | 5721 | 4571 | 1150 | 1907 | 132 | 805 | 0 |
| `--llm` + **ERRFIX=0** | **6045** | **5053** | 992 | **1720** | **103** | **371** | 22 |
| `--llm` + **ERRFIX=1** | 6020 | 5021 | 999 | 1735 | **103** | **371** | **12** |

**读法（这一条比数字本身重要）**：

- `--llm` 单独就贡献了**几乎全部**指标涨幅（5721 → 6045）；
- 白名单在**长度类 stdout 指标上略差**（6020 < 6045，1735 > 1720），
  但在**三道人眼级门禁上完全一致**（qa 103 · bookscan 371 · eqcheck exit 0）；
- 长度指标**就是 DP 自己的目标函数**（§1.1：它天然偏向 DP、检测不出语义错配）
  ⇒ **不能拿它给白名单打分**。拿它打分等于让 DP 给自己的答案判卷。

⇒ **白名单的真实、可辩护的收益**：省 10 次 LLM 请求、成本减半、
**避开未确认的 >32k 计价档**，且质量中性。**不要说它"提指标"。**
**更重要的收益是防劣化**：见下。


### 日志自证（排查用）

旧日志只有 `(章首)` + 判定，**看不出是哪一节**。本轮排查「中文独有章触发 8 次、
但只声明了 5 个中文独有章」时完全无法定位，只能回头翻代码推理。现给

## 三、LLM 那边的接口设计

### 3.1 窗口形状：给「上下文 + 候选分组」，不给全文

```jsonc
// 输入（单窗口）
{
  "task": "block_align_verify",
  "en": [                      // 英文侧：带索引的块文本（含公式图占位）
    {"i": 11, "t": "With these understandings, Boolean algebra is characterized by…"},
    {"i": 12, "t": "{{IMG:eqn01_39a.jpg}}"},          // ← 图位是显式占位符
    {"i": 13, "t": "The proposition"},
    {"i": 14, "t": "If B = AD, then…"}
  ],
  "zh": [
    {"j": 17, "t": "幂等性：$\\left\\{…"},
    {"j": 18, "t": "若 $\\overline{B} = AD$, 则…"},
    {"j": 19, "t": "{{IMG:eqn01_40.jpg}}"},
    {"j": 20, "t": "命题"}
  ],
  "dp_hint": [[11, 17], [12, 19], [13, 18], [14, 20]],  // 现行 DP 结果
  "suspect": ["en[13] 配 zh[18]，但 zh[18] 公式密集、en[13] 是短正文"],
  "constraints": "只能做**块级 N:M 分组**；不得在段内切边界；必须覆盖所有块"
}

// 输出
{
  "groups": [
    {"en": [11], "zh": [17]},
    {"en": [12], "zh": [19]},
    {"en": [13, 14], "zh": [20]}     // ← 裁决：13 的译文是「命题」，14 配给 20 后的段
  ],
  "reason": "en[13] 'The proposition' 对应 zh[20] '命题'；zh[18] '若 B=AD…' 是 en[12] 图的译文",
  "confidence": 0.82
}
```

**要点**
- `{{IMG:…}}` **显式占位**：把英文公式图的位置变成 LLM 看得见的结构信息
  （§6.15 说"真正能区分的是英文侧是不是公式图"——这里就把它喂进去）；
- `dp_hint` 作为先验给 LLM，让它**改**而不是**重排**（防 §6.13 的灾难）；
- `constraints` 把用户铁律写进 prompt，而非靠模型自觉。

### 3.3 安全阀（必须写进实现）

1. **覆盖率自检**：LLM 返回的 groups 必须恰好覆盖窗口内所有 en/zh 块，
   否则**丢弃该窗口的裁决**、退回 DP 结果（防 LLM 丢段）；
2. **改动幅度上限**：若一个窗口的裁决改动了 > 60% 的对，标记为 `suspect_llm`
   并**不采纳**（§6.13 的 88% 搬空就是这么来的）；
3. **可复现**：窗口与 prompt 必须落盘（`tools/.cache/errfix/<hash>.json`），
   裁决结果也落盘 → 重跑零成本、可审计；
4. **不 bump `_V`**：勘误在**对齐之后**、**渲染之前**，只改 pair 表，
   不改解析行为。

## 四点五、⚠ 排查纪律（本篇最重要的一条）

遇到「整块只有英文 / 零中文 / 大段对不上」时，**按此顺序排查**：

1. **先查解析器有没有丢标题**（免费、1 秒）。
   判据：**两侧小节数悬殊而总段数接近** → 一定是切分问题。
   例：附录A `EN 6 节 / ZH 1 节`，段数 86 / 88。
   工具：`tools/dbg_sec*.py`、`tools/dbg_appA.py`。
2. **再查是不是「单侧本就是正确答案」**（免费）。
   判据：中文独有段里的数字/拉丁串在英文全章**完全找不到**（`dbg_zhonly_locate.py`）。
3. **最后才怀疑对齐算法，才考虑请 LLM。**
   并且必须能说清「DP 为什么在这里必然错」，而不是"看起来不对"。

**反面教材（本会话累计 4 次假结论，全部出在自己写的检测脚本上）**：

| # | 我的错误写法 | 导致的假结论 | 真相 |
|---|---|---|---|
| 1 | `<(div\|p\|table)[^>]*>(.*?)</\1>` 非贪婪 | 「1305 个公式格里含中文（78%）」 | **0 个**（嵌套切错，整段被吞） |
| 2 | `re.findall(r'<div class="pair">(.*?)</div>', ...)` | 「1059 对只有英文没中文」 | 切片错位，数字巧合 |
| 3 | 同 #2 + 按标题位置推断 | 「6.5 节有 373 个只英文」 | 该节结构**完全正确** |
| 4 | 只认 `<p class="zh…">` | 「40 个空 pair」 | 引文是 `<blockquote class="zh…">`，**0 个空 pair** |

⇒ **铁律：结论只许来自「只数标签」或「读原始 HTML 片段」**；
任何需要"嵌套配对"的正则，先怀疑它，不要先怀疑流水线。
