## 4. 环境与坑（浓缩，详版在 `.workbuddy/memory/MEMORY.md`）

- **WSL 唯一**：`wsl.exe -- bash <项目>/tools/_run.sh <脚本> [参数]`；
  `wsl.exe -- bash -lc '...$VAR...'` 的变量会被 Windows 层吃掉。
  `_run.sh` 有护栏：cwd 不在项目内直接 exit 3。**WSL 只许碰项目目录**。
- 缓存：解析缓存在 WSL 原生盘 `~/.cache/bil`（`tools/.cache` 是软链）。
  **`.cache/*` 永不删 = 缓存就是钱**。`build/`、`diag/` 用户自己删。
- node 用 nvm 那份（`tools/eqrender` 要 ≥20.9）；**绝不在 /mnt/c 上 npm i**。
- 截图验证：`msedge --headless=new --disable-gpu --window-size=900,2300
  --screenshot=out.png file:///…`（不启服务）。
- **别用 `git rm`**：本轮实测 `git rm` 被 SIGTERM 打断后 `.git/index.lock` 残留
  + 工作区 56 个文件被连带清掉（含 `_run.sh`/`run_book.py`）。
  恢复配方：`rm -f .git/index.lock` → `git status --porcelain | awk '$1=="D"{print $2}'
  | xargs git checkout HEAD --`。要删文件就用普通 `rm` + `git add <路径>`。
- 代码整理时留下的**零引用探针**（可删，本轮没删是为了避开上面的雷）：
  `tools/dbg_heads2.py dbg_fig.py dbg_fig2.py dbg_wide2.py dbg_skew.py
  dbg_skew_stat.py dbg_eq_demo.py` + 根目录 `book_struct.json`。

#### Fix #2：md 附录的**裸行子节标题**（`tools/bil/txtimport.py`）

**病象**：中文 md 的附录里，子节标题是**没有 `#` 前缀的裸行**：

```

```

`_MD_HEAD_RE`（要有 `#`）和 `_bare_head`（≤12 字、且必须全长匹配 `_ZH_HEAD_RE`）
**两条都不认** → 整个附录被解析成 **1 个 section**（中文 88 段 vs 英文 6 节）。

**修法**：新增一个**只认附录子节**的裸行判据，命中后**在当前文档内**追加
一个 `level=2` 的 heading 块（**不开新文档**）：

```python
_APX_SUBHEAD_RE = re.compile(r"^([A-Z])\.(\d{1,2})(?:\.\d{1,2})?\s+\S")

def _bare_subhead(line: str, lang: str) -> str:
    """裸**子节**标题（附录 A.1 / B.3 …）。命中返回标题文本，否则空串。"""
    if lang != "zh":
        return ""
    t = (line or "").strip()
    if not t or len(t) > 60:
        return ""
    if not _APX_SUBHEAD_RE.match(t):
        return ""
    if t.endswith((".", "。", ",", "，", ";", "；", ":", "：")):
        return ""
    return t
```

⚠ **为什么不用「加进 `_ZH_HEAD_RE`」**：那会把 `###` 级也判成章、把单元切碎
（§6.6 已经警告过）。这里必须**只做 heading 块、不开新单元**。

### 6.24 ★★★ 用户点名的「标题中文对齐错误」= 标题与正文**次序相反**（2026-09-18 14:3x）

用户从第一天就报「**标题中文对齐错误**」，我查了几轮都没定位（§6.21 我去修
fm-title 解析，修完了 `bookscan` 全 0，但那个症状**没消失**）。这一轮找到真根因，
**并且发现我自己的三把尺子全都测不到它**。

#### ① 症状（中文读者视角）

```html
<body class="ord-zh dim-en">
  <h2 class="ct en-h">Editor’s foreword</h2>   ← 英文标题
  <h2 class="ct zh-h">编者序</h2>              ← 中文标题
  <div class="pair">
    <p class="zh zh_transed">埃德温·汤普森·杰恩斯于1998年4月30日去世…</p>
    <p class="en en_original">E. T. Jaynes died April 30, 1998…</p>
  </div>
```

读者看到：**英文标题 → 中文标题 → 中文正文 → 英文正文**。
中文标题被夹在英文标题和自己的中文正文之间 —— 标题与正文脱节。
这就是「标题中文对齐错误」。截图对比见
`.workbuddy/tmp/real_prob_p4.png`（错）vs `real_prob_p5.png`（对）。

#### ② 根因：同一个 xhtml 里存在**两种顺序约定**

| 位置 | 谁在发 | 次序 |
|---|---|---|
| `.pair` **内部** | `_reorder_pairs(zh_first=True)`（build.py:2556） | **zh 先、en 后** |
| **标题** h2/h3/h4 | `_head_block()`（build.py:436） | **en 先、zh 后** ← 相反 |

`_reorder_pairs` 只重排 `<div class="pair">` 的子树；**标题在 pair 之外**，
从没被它碰过。而 `_head_block` 里的两个 `if` 顺序是 en 在前、zh 在后。

为什么 CSS 救不了：`ORDER_CSS` 的 `.ord-zh .pair > .zh { order: 1 }` 是
**后代选择器挂在 `.pair` 上**，标题不是 `.pair` 的子元素 ⇒ 规则不生效。
即 **DOM 顺序就是阅读器看到的顺序**（这也是 `_reorder_pairs` 存在的原因）。

#### ③ ★★★ 为什么三把尺子全绿 —— 判据正交

| 尺子 | 量的是什么 | 为什么不报 |
|---|---|---|
| `dbg_qa.py` ① | 「≥3 个同侧长段连成坨」 | zh/en **完美交替**，一个同侧串都没有 |
| `dbg_order.py` ①② | `.pair` **内部**谁在前 / 单侧段 | 标题**在 pair 之外**，扫不到 |
| `dbg_bookscan.py` | 行号前缀 / 标记泄漏 / 整篇缺中文 | 与次序无关 |

⇒ **「标题对齐错」在两把顺序尺子的作用域之外。** 这不是书没问题，
是**尺子覆盖面**问题 —— 与 §6.20、§6.22、§6.23 是同一类错误的第 3、4 次复发。

#### ④ 修法（`2db6b65`，渲染层，无缓存影响）

1. **`_head_block`：发射次序改为 zh 先、en 后**，与正文同一约定。
   在 docstring 里写死这条约定：**DOM 顺序一律「中文在前」**。
2. **CSS 紧挨规则跟着翻面**。原设计是「en 带小下间距 `.22em` + zh

### 6.23 ★★★ 题注（caption）三连缺陷 —— 尺子「测不出」的第二种形态（2026-09-18 14:0x）

### 6.21 ★★ 序言~第二章的「标题对齐错」= 解析器丢了 `fm-title*` 卷头标题（2026-09-18 13:5x）

#### ① 根因：英文原版卷头标题的 class 是 `fm-title*`，解析器**一个都不认**

英文 epub 里卷头标题长这样（`prob_en.epub`）：

```html
<p class="fm-title2"><a id="page_xvii"/>Preface</p>          ← 08_fm-chapter1.html
<p class="fm-title2"><a id="page_xvii"/>Editor’s foreword</p> ← 07_fm-chapter.html
<p class="fm-title2">Contents</p>                             ← 06_toc.html
<p class="fm-title">PROBABILITY THEORY</p>                    ← 02_half-title.html
<p class="fm-title1">THE LOGIC OF SCIENCE</p>                 ← 02_half-title.html
```

`_semantic_type()`（`epubparse.py:375`）判 heading 的两条路**都不匹配**：

| 判据 | 正则 | `fm-title2` 为什么不过 |
|---|---|---|
| `_CLASS_HEAD_RE` | `(?:^\|[\s_-])h([1-6])(?:[a-z])?(?:[\s_-]\|$)` | 类名里**没有 `hN`** |
| `_CLASS_TITLE_RE` | `(?:chapter\|section\|part)[\s_-]?title` | **没有 chapter/section/part 前缀** |

⇒ 落到 `return "para"` —— **卷头标题被当成正文段**。

**中文侧却是有标题的**（`prob_zh.md` 里是 raw markdown `### 前言` / `### 编者序`），
⇒ **英文少一个标题、中文有一个** ⇒ 该标题起的小节配对**整体左偏一格**。

### 6.8 修掉「中文小节标题重复渲染」（2026-09-17 22:1x，commit `82c43b6`）

**病象**：成品里同一句中文小标题出现**两次** —— 一次是 `h4.st.zh-h`（对），
一次是 `p.zh.zh_transed.zh-orphan`（重复）。实测 50 段，典型
`3.8.1「离题：关于现实与模型的说明」`、`1.5「蕴涵关系」`。

**根因**：`pipeline._extract_zh_titles` 把这类标题段**从 `p.zh` 里摘走**
（挂到 EN 原位标题旁渲染），但 `build.py` 的 orphan 判定
`_claimed = {j for _p in sec.pairs for j in (_p.zh or [])}` **只看 pairs** ——
摘走的段不在里面 → 被判「未配对的中文段」→ 兜底再渲染一次。

**修法**（纯渲染层，**不碰对齐决策、不 bump `_V`**）
1. `_claimed` 并入 `sec.zh_heads_at` 的段号；
2. 两处 `_zh_hp` 渲染（`build.py:1171` / `:1268`）补 `_emitted_zh.add(...)` ——
   标题已以 h4 发出，末尾「中文段是否全渲染」的自检不该再报它「丢失」
   （漏这步时自检会从 0 涨到 **36**，是假警报）。

**验证**：兜底渲染 **50 → 14** · 自检报警 **0** · 成品里
`离题：关于现实与模型的说明` 命中 **2 → 1**（且是正确的 h4）·
指标 6067/4893/1157/17/1838 **不变** · `bookscan` 0/0/0 · `eqcheck` exit 0 ·
regress **零变化**。

**排查手法（可复用）**：`grep -c "兜底渲染\|自检!" <build.log>` 两个计数
一起看 —— 单看「兜底渲染变少」会以为修好了，其实自检已经在喊「有段没渲染」；
**两个指标必须同时归零/回落才算真修好**。

### 6.7 修正 §3.3：无法复现，但查出一个相关的真 bug

**复现尝试全部落空**
- 第7章 = 成品 html 的 `id="ch8"`（offset 9214753）。它到下一个
  `<div class="notes">` 之间隔了 **17.7 MB** —— 即第7章**根本没有注释区**。
- 全书 `<div class="notes">` 只有 **2 个**（`ch25` 附录B、`ch29` 人名索引），
  `<b>[29]</b>` 命中 **0 处**。用户正式成品 `diag/样章/prob_全书_双语.html`
  更少（**1 个**，只有 `ch25`）⇒ ②④ 之后**反而多了一个**。
- `ch25` 那个「注释」是 **`cut_notes` 误判**：它的 `[1]` 文本 =

  那是**附录B 正文的最后一段**，被当成注释从正文里摘走了。

**中文版的注释到底在哪**：**源稿里没有**。全书 grep

圈码标记（`$^{①}$`，如源稿 126 行），**没有对应的注释正文**。
⇒ 「注释对不上」更可能是**源数据本身缺注释**，不是编号错位。

**⇒ 查出的真 bug**：`build.py:1424` 的 `if res.notes:` 把**英文兜底也挡在门内**。
该块的设计意图是（`:1428` 注释原文）「中文版注释可能少于英文（逆向版本不全）。
缺的条目用英文原文兜底，避免正文里的 [n] 指向空锚点」，但兜底循环

**修法**（未做，属内容决策）：`if res.notes or _ids:`，并把两个循环都留在块内。
