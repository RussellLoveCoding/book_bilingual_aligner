# 上手指南

> 这份文档写给**不写代码的人**。全程只需要「装一次、点几下」。
> 想深入技术细节的，看左侧「技术文档」那一组。

## 这是什么

把**英文原书**和**中文译本**合成一本**段段对照**的电子书 ——
读的时候英文一段、中文一段挨着排，方便对照原文。

```
输入：英文 epub  +  中文 epub
输出：双语 epub（英文骨架，中文译文挨着插进去）
```

## 一、装一次（只做一次）

### 1. 装 Python

去 [python.org/downloads](https://www.python.org/downloads/) 下载安装包，一路「下一步」。
**安装第一屏记得勾上 `Add Python to PATH`**（不勾后面命令会找不到）。

验证：打开终端（Windows 按 `Win+R` 输入 `cmd` 回车），敲：

```bash
python --version
```

能打印出版本号（如 `Python 3.12.x`）就成了。

### 2. 拿到这个项目

把项目文件夹整个复制到你电脑上任意位置，比如 `D:\bilingual-ebook`。

### 3. 启动

在项目文件夹里打开终端，运行：

```bash
python tools/app.py
```

看到 `http://127.0.0.1:8765` 就说明起来了，浏览器会自动打开。
**这个终端窗口不能关** —— 关了服务就停了。用完按 `Ctrl+C` 退出。

> 如果浏览器没自动开，手动访问 `http://127.0.0.1:8765`。
>
> 端口被占用（提示 `Address already in use`）就换一个：
> `python tools/app.py --port 9000`

## 二、出书：三步

### 第 1 步 · 选文件

在「合成」页面，拖入或点选两个文件：

| 位置 | 放什么 |
|---|---|
| **英文原书（结构骨架）** | 英文原版 epub |
| **中文译本（译文血肉）** | 中文版 epub |

支持 `epub` / `txt` / `md`。**成品格式随输入**：两边都是 epub 就出双语 epub；
任一边是 txt/md 就出中英对照文本。

### 第 2 步 · 起个书名（可选）

不填就自动从文件名里猜。书名会印在成品封面和目录上，也决定成品文件名。

### 第 3 步 · 点「开始合成」

进度条走完就出结果了。点「下载中英对照 epub」拿走成品，
或点「在线预览 HTML」直接看效果。

## 三、先试试看（不用准备文件）

页面上有个 **「载入测试样本（第 5 章）」** 按钮，点一下会自动载入一对样例，
你可以先跑一遍感受下流程，**不花钱**。

另外左侧「**试对齐**」可以粘贴任意中英段落实时看对齐效果 ——
**但那个结果不准，只用来感受格式**，原因见下。

## 四、要不要开 LLM？

页面上「启用 LLM」这个勾选框决定两件事：

| | 不勾（默认） | 勾上 |
|---|---|---|
| 速度 | 约 1 分钟 | 视篇幅，通常几分钟 |
| 花费 | **¥0** | 按 token 计费，一本书通常几毛到几元 |
| 效果 | 纯算法对齐 | 多几层智能处理（见下） |

**勾上之后多做什么：**
- **细化解码** —— 疑难段落让 AI 再判一次
- **内容审查修复** —— 把中文版因审查删掉的段落按英文补回来（**科普/技术书别开**，会误判）
- **缺失段 AI 补译** —— 中文版没收的段（多是前后附页）用 AI 译出

> **建议**：第一次先不勾，跑通流程看效果；满意了再勾上重跑一遍对比。

## 五、LLM 配置怎么填

展开「LLM 设置」，点一个预设按钮自动填好：

| 服务商 | 说明 |
|---|---|
| **通义千问** | 本项目一直在用的，推荐 |
| DeepSeek / OpenAI / Moonshot | 都行，填自己的 key |
| 本地 Ollama | 完全免费但要本地跑模型，慢 |

**需要自己填的只有两样：**
1. **Base URL** —— 点预设按钮自动填
2. **API Key** —— 去服务商官网申请，形如 `sk-xxxxxx`

填完点「**测试连接**」看通不通，通则点「**保存到 .env**」存起来（下次不用再填）。

> ⚠️ **key 是你的钱袋子**，别截图发人、别传到网上。
> 保存在项目根目录的 `.env` 文件里，不会上传到任何地方。

## 六、注意事项（重要）

### ⚠️ 关于「试对齐」页面

那个页面**结果不准，仅供示范**。它只拿到「纯段落清单」，
不走完整流水线（不做章节映射、不认标题/题注/公式图、不做勘误），
所以只对**干净、无复杂排版的纯文本**比较有效。
**别用它判断成品质量**，要看效果请用「合成」页跑出来的成品。

### ⚠️ 什么书效果最好

| 效果好 | 效果差 |
|---|---|
| 英文原版 epub 结构清晰 | 扫描件 OCR 出来的、错字多 |
| 中文译本段落比较规整 | 中文版章节大改、合章拆章 |
| 科普 / 技术 / 非虚构 | 诗集、剧本、大量图表排版 |

**对齐的前提是两边能大致对上**。中译本如果重排得很厉害，
对齐会吃力 —— 这是所有跨语言对齐的共同难点，不是这个工具的锅。

### ⚠️ 成品要先翻一遍

自动对齐**不可能 100% 正确**。成品里：

- 带「**AI译**」标记的段落是 AI 补的，最好核对下
- 带「**审修**」标记的是按英文补回的，看看要不要
- 偶尔有段落配错位置 —— 遇到请记下来，这是改进的线索

### ⚠️ 别中断服务

合成过程中别关终端窗口、别刷新页面。中途断了要从头跑。

## 七、常见问题

**Q：浏览器打不开页面？**
先确认终端里服务还在跑、没报错，再手动访问 `http://127.0.0.1:8765`。

**Q：提示找不到 `python` 命令？**
装 Python 时没勾 `Add Python to PATH`。重装一遍并勾上；或改用 `py tools/app.py`。

**Q：卡在某一步不动了？**
勾了 LLM 的话可能是在等接口返回。看页面下方日志，实在不动就 `Ctrl+C` 重启。
开了 LLM 的话**已处理的部分会走缓存**，重跑不会白花钱。

**Q：花钱会不会失控？**
跑完页面会显示本次实际花费。想更稳妥就用不勾 LLM 的纯算法模式，一分钱不花。

**Q：成品在哪？**
页面结果区会显示「产物目录」的完整路径，「下载」区的按钮直接取文件。

**Q：能只跑几章试试吗？**
可以。「只跑指定章节」填逗号分隔的章号，如 `chapter1,chapter5`。
（章号是**英文原书**里的文件名，不确定就先留空跑全书。）
